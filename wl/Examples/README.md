# wl/Examples

Runnable example terms, one folder per example. Each folder may hold:

- `term.wl` (required) -- the input term construction. Final value
  is what `THeapGraph` is seeded with.
- `term-reduced.wl` (optional) -- the *expected* WHNF of `term.wl`,
  built directly (no `TWnf` / `TReduce`).  The reduction test runner
  compares `TTermTree[TWnf[term.wl]]` against `TTermTree[term-reduced.wl]`.
- `term.hvm` (optional) -- the same term in HVM4 surface syntax with
  the expected output as a `//` comment line.  Documentation only;
  we don't have a parser yet.
- `term.png` -- generated by `make wl-examples`; the `THeapGraph`
  rendering of `term.wl` on a dark theme.

The `term*.wl` files carry no boilerplate -- no `Needs[...]`, no
`TInit[]`. The runner sets up the paclet and the runtime.

## Commands

```sh
make wl-examples                          # render every term.wl
make wl-examples EXAMPLE=id-app-era       # render one folder
make wl-examples-test                     # run the tree-comparison reduction tests
```

Or directly:

```sh
wolframscript -f wl/Examples/run.wls
wolframscript -f wl/Examples/run.wls dup-sup-annihilate
wolframscript -f wl/Examples/run.wls dup-sup-annihilate --eval
wolframscript -f wl/Examples/test_reductions.wls
```

`--eval` runs the example without writing any PNG -- useful for
sanity-checking what the WL evaluator returns.

syntax; the trailing `//<value>` line is the expected reduction.

## Adding an example

1. Create a new folder (hyphenated name).
2. Drop a `term.wl` whose final expression is the term to render.
   Use `TFreshLabel`-backed `TSup[a, b]` / `TDup[body, k]` unless you
   specifically need an explicit label.
3. If the term has a meaningful WHNF, also drop a `term-reduced.wl`
   that constructs that expected value directly.
4. (Optional) drop a `term.hvm` reference using HVM4 surface syntax
   plus a `//<expected>` comment.
5. Run `make wl-examples EXAMPLE=<your-folder>` to render `term.png`.
6. Run `make wl-examples-test` to confirm the reduction matches.
