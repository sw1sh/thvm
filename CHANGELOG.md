# Changelog

High-level log of meaningful changes. Newest first. Consult `git log`
for the per-commit story.

## Unreleased

### Runtime
- `thvm.h` loses six macros nothing used (`SUB_BITS`, `TAG_BITS`, `EXT_BITS`, `VAL_BITS`, `VAL_SHIFT`, `DUP_LABEL_MASK`), the retired `KDISPATCH_METAL_JIT` and `KDISPATCH_CPU_TILE` entries with the tombstone note for 11 and 12 (every remaining kind keeps its explicit number), and the uncalled `thvm_metal_buf_byte_offset` (the Metal binds read the buffer's `byte_offset` directly).
- Firing a kernel the kernel GC stripped fails the realize (`thvm_realize` returns 0 with "realize fired kernel kid=N, which the kernel GC stripped"; py raises RuntimeError) instead of running nothing and leaving the output buffer's stale bytes; outside a realize it aborts with the kid.  `kernel_gc_sweep` marks the slot `stripped`.  On main, `test_transformer_block_parity::test_train_muon_descends` printed 48 such no-op fires and passed; the Muon fix removed them, and the full py and NN C suites raise none.
- The heap collector undoes a realize's in-place TAG_TEN substitutions before it copies the heap, re-keys the loc -> tid cache and the shared-tid locs to the moved cells (it cleared them, except inside a JIT-capture span, which kept stale keys), and moves `TenDesc.grad`.  A collection at the realize boundary ran before the realize's own journal restore, so the restore wrote into dead from-space and the surviving graph kept leaves naming tids whose buffers the rollback had freed; a lazy gradient left in `TenDesc.grad` kept pointing into the old space.
- The WL lambda tables copy a CAST's and a BITCAST's `[src, NUM(dtype)]` into the book snapshot (`dyn_arity`) and a CAST's, a BITCAST's and a CMPEQ's cells into an ALO realize (`alo_node_arity`), as `lam_body_arity` already walked them. Both passed such a node through with its old heap location, so a lambda body holding one (a half gather's adjoint casts f16 to f32 and back) read stale cells: `test_uop_gather_scatter_ir` 174/182 before, 182/182 after.
- The WL lambda tables (`lam_body_arity`, `alo_node_arity`, `dyn_arity`) walk a select's three children, as they walk a gather's and a scatter's: an IWHERE was an arity-0 atom there, so a book snapshot kept the dynamic heap cells of a lambda body holding one (the value selects `uop_where` builds, a WHERE imported from tinygrad), ALO realize copied none of them, and a binder used only inside a branch read as unused. The kernel content hash (Metal pipeline and autotune cache key) reads a GATHER's dim and a SCATTER's dim, kind and include_self, not only their children.
- ASSIGN into a view of packed nibbles (i4 / u4) that starts or ends inside a byte writes only the view's nibbles and keeps its neighbours'. It copied whole bytes from the element offset rounded up, so a 3-element view at element 1 of 9 landed at elements 2-4 and zeroed element 5. No realize reaches it yet: a shrink of an i4 tensor leaves its ASSIGN unfired.
- A mismatched ASSIGN reads each source value in the source dtype's lane, as a CAST kernel does: a float stored into a bool is x != 0 and an int reaches a float rounded once, a u64 from its unsigned value. It picked the lane by the destination, so f32 0.5 stored into a bool gave 0 (a realized CAST gives 1), i64 2^60 + 2^36 + 1 stored into f32 went through a double to 2^60 (C's (float) gives 2^60 + 2^37), and u64 2^63 + 2^39 + 1 gave 2^63.
- The f16 encode fallback (no `_Float16`) rounds as the builtin does. It encoded every f32 between 2^-25 and 2^-24 as 0 instead of the smallest subnormal, dropped the bits it shifted out before rounding a subnormal (a value just past a tie rounded down), and gave every NaN the same payload. `f32_to_fp16_manual` is built on every platform; `test_fp16_convert` checks every mantissa of the binades where subnormals, normals, inf and NaN meet, plus a sweep of all f32, against an exact reference and, on x86, against F16C.
- The f16 decode fallback, used where the compiler has no `_Float16` (gcc 11 on the x86 Linux pods), decodes every pattern as the builtin does. It put subnormals one binade low, so every f16 and fp8e5m2 subnormal read back at half its value there, and it let a signaling NaN through unquieted. `fp16_to_f32_manual` is now built on every platform; `test_fp16_convert` holds it and `fp16_to_f32` to an exact reference for all 65536 patterns, and the reference to the F16C instruction on x86.
- ASSIGN writes every dtype, and a JIT capture replays it: matching dtypes copy the storage bytes (an fp8, f16, bf16, bool, 1-, 2- or 8-byte int or packed-nibble destination was left unwritten; only f32 and i32 copied). Differing dtypes store the source values at the destination dtype, as a CAST kernel would (an i32 source was copied into an f32 buffer as raw bits). tinygrad casts a weak value to the target dtype before assigning (tensor.py:243) and raises on a strong mismatch (tensor.py:244).
- The kernel content hash (Metal pipeline cache and autotune cache key) includes each buffer's input slot: `x*x+y` and `x*y+y` hashed equal, so on Metal one kernel could reuse the other's pipeline. Autotune caches on disk re-tune once.
- The garbage collector refuses to build when a UOp opcode is added without a heap size in `gc_node_size` (a missing size leaves live nodes of that op unevacuated), and the UOP_BUFFER constructor documents its instance cell.
- Fix: the copying collector keeps every UOp node whole.  A live RANGE lost
  its extent and a BUFFER its last dim (both were sized one cell short), and
  BUFFERIZE, END, STACK, GEP, UNROLL, CONTRACT, VCONST, PLACEHOLDER and
  DETACH nodes were never copied, so after a collection a kernel's content
  hash (the Metal PSO / tile-JIT / autotune cache key) and its ranges changed.
- A realized fp8 constant fills through the kernel-store rule, as tinygrad realizes a constant in a kernel: an fp8e5m2 +/-inf CONST (broadcast, 0-d, reshaped, or a CAST that folds to one) fills as 0x7b / 0xfb (maxnorm), not 0x7c / 0xfc. The CONST payload and BITCAST / CAST folds keep inf.
- JIT capture: sinking a dispatch into an assign's buffer now checks replayable gathers too, so a realized view of that dispatch's output keeps reading fresh bytes on replay (the sink only runs for Metal tile kernels). Gather endpoints are retained with the capture like other ops' buffers, and the profiling export shows gather rows.
- fp8 conversion follows tinygrad's two rules. Host conversion (CONST payloads, CAST/BITCAST folds, WL writes) is `float_to_fp8`: every e4m3 non-finite is NaN, and e5m2 keeps inf. CPU kernel stores follow the emulated kernels' saturating narrow, so a runtime cast of -inf to fp8e4m3 stays -448. The MAX identity is `dt.min` (-448 for e4m3), as in `identity_element`.
- Term packing, flat heap, WNF stack machine, 29 interaction rules.
- Parallel WNF: atomic heap primitives, work-stealing deque,
  persistent worker pthreads (`THVM_THREADS`).
- Multi-context API in progress: `TContextSnapshot`, slice trace,
  multiway and causal graphs.

### Tensors & Autograd
- An amin scatter's gradient gives a losing branch -0.0, as tinygrad's negated MAX does, so all 308 gradient cases pinned to tinygrad master are bit-exact including zero signs.
- Chain rule through `UOP_SCATTER` MAX and MIN (`grad_scatter_maxmin`): tinygrad's gradient of its dense amax `M.maximum(T)` (mixin/op.py:1129) through its MAX, REDUCE MAX and WHERE rules (mixin/gradient.py:78-79, 10-13, 81). Tied maxima split the cotangent evenly, a tie between the src maximum and the base gives each side half, an untouched base equal to the identity keeps half, the tie count includes the one-hot's non-hits when the maximum is the identity, and an invalid id gets 0; the src maximum is recomputed by a scatter, the count is one more scatter-add accumulated in sum_acc_dtype, and the rest are gathers and elementwise ops, so the backward stays O(|base| + |idx|). PROD and REPLACE still raise the grad error. `test_grad_scatter_max` (single walk, target and legacy modes, both CPU routes) pins a tie-heavy case to tinygrad master's own gradients and covers tie-rich data, finite differences, a computed src, linear backward kernels under JIT capture with replays, half and a GC before the realize: 475/902 before, 2876/2876 after; `test_grad_gather_scatter` and py's bridge test now take PROD as the kind without a rule.
- `docs/gather_scatter.md` and `docs/thvm_vs_tinygrad.md` list a gather or scatter index outside the int32 range as a deviation: the kernels compare the index as an int32, the width of every kernel address, and py's `Tensor` stores an int64 array as int32, so 2^32 + 1 reads row 1 where tinygrad reads 0. Only the `ru_lower_gather` comment said so.
- `bin/test_grad_gather_scatter` checks that a half gather's gradient
  accumulates in float32: three cotangents 2048, 1, 1 on one row give 2050,
  where half accumulation stays at 2048.
- Chain rule through `UOP_GATHER` and `UOP_SCATTER(SUM)`, the gradients of
  tinygrad's one-hot gather and scatter_reduce sum (mixin/op.py:1041,
  :1127): a gather's src gets the cotangent scatter-added back (accumulated
  in float32 for 16- and 8-bit floats, as sum_acc_dtype), a scatter's src
  gets it gathered, its base gets it as is or, without include_self, with
  the written positions zeroed (a REPLACE scatter, tinygrad's `_inv_mask`);
  the index gets none and the single-walk pre-walk credits no index slot.
  No backward builds a one-hot or a REDUCE.  PROD / MAX / MIN / REPLACE
  scatters have no rule yet: their cell fires to zero and the new chain-rule
  error slot (`grad_err_set` / `grad_err_take`) names the kind, where the
  cell used to stay unfired with no message.
- New indexed UOps (IR only, no lowering yet): `UOP_GATHER` (tinygrad
  `Tensor.gather`, mixin/op.py:1023-1043: an out-of-range index reads 0) and
  `UOP_SCATTER` with SUM / PROD / MAX / MIN / REPLACE kinds and include_self
  (tinygrad `scatter_reduce` / `scatter`, :1126-1177).  `uop_gather` /
  `uop_scatter` check the operands the frontends validate and return 0 on a
  mismatch; `scatter_identity_bits` gives tinygrad's exact identities
  (dtype.py:70-78).  Every per-op table knows them: arity, shape, dtype,
  graph-rewrite rebuild, GC cell size, the WL lambda copiers, and the py /
  WL opcode names.
- Chain rule through a value select: `IWHERE(c, t, e)` sends the cotangent to
  the selected branch and none to `c` (tinygrad mixin/gradient.py:81), and the
  single-walk pre-walk credits only those two slots.  New `uop_where` builds a
  value select without `uop_iwhere`'s index-layer folds (which turned nested
  selects into an unschedulable tensor-level IAND); the py tinygrad importer
  maps WHERE and MAX through it, so imported WHERE graphs are differentiable.
- `TTensor` + `TUOp` graph (const / unary / binary / reduce / movement / Conv2D).
- Autograd via `UOP_GRAD`; chain rule through Conv2D, Softmax,
  Pooling, ReLU, Tanh, Reshape, Flatten, ...
- `TOptim["SGD"]`, `TOptim["Adam"]` as recursive lambda terms.
- Einx-style verbs over TUOp (`wl/THVMLink/Kernel/Einx.wl`).

- A realize that would compute a packed int4 / uint4 buffer stops in `bufferize_classify` with `thvm fatal: bufferize: no kernel computes a buffer of dtype i4` (or u4), which single-root `TRealize` and a kernel fire return as a failure (`TRealize[{...}]` and `TMaterialize` arm no recovery, so there it still ends the process); `test_bufferize_classify` checks the stop for an int4 ADD, a 0-d int4 SUM and a uint4 NEG.  The stop used to be a side effect of the bufferize cost pass sizing every realized buffer with `dtype_itemsize`: it aborted the process, a WolframKernel included, and it skipped 0-d results, so an int4 SUM to a scalar returned a wrong value.
- A strided view root over a kernel output a sibling root's pass cached (a broadcast EXPAND) is emitted as a copy kernel that fires after its producer, as a chained view root already was; only a plain contiguous alias skips the kernel.  The root was gathered on the host at materialize time, before any kernel fired, so `(Bp + (x @ W1).gather(0, idx)).sum(1, keepdim=True)` handed the optimizer a zero grad for Bp, silently, on main too: Bp never moved, where tinygrad updates it.
- A view of a kernel output that survived a realize is a leaf, as the output tid itself already was: `kernel_gc_sweep` clears the producer kid of every TenDesc that shares a live output buffer, not only the output tid's.  A realize that returned such a view (Bp's grad behind `o @ W2` in `o = Bp + (x @ W1).gather(0, idx)`) kept the kid, so the optimizer update re-fired that chain over stripped kernels (`kid=2 n_inputs=0 ran no dispatch rung`) and overwrote the grad: Bp's update was off by up to 2.0e-4 out of 2.1e-3 in SGD, fused or split, both CPU routes, any GC threshold, with or without the arena planner.
- A realize root that another root of the same bundle also reads is held like every root: the arena and freelist planners never recycle it, as tinygrad's memory planner never plans the buffers a call returns (schedule/memory.py:11-12, held_bufs from schedule/__init__.py:303).  The planners skipped only roots with no in-pass consumer, so in `loss.realize(*opt.schedule_step())` on `Bp + (X @ W).gather(0, idx)` Bp's grad, an input of W's grad kernel, got an arena slot; the realize freed it, the kernel GC stripped its producer, and the param update re-fired that kernel with no inputs and segfaulted (SGD and Adam, eager and TinyJit, both CPU routes).
- The movement-op hash-cons cache (`uop/mov_cache.c`, which also hash-conses `UOP_BUFFER` and REDUCE) doubles before it passes half full.  Its fixed 2^18 slots filled up in a long process (the py suite reached it during `test_cat_parity`): later inserts were dropped and every miss scanned the whole table, so equal UOPs became distinct Terms.  The CPU renderer names a kernel's input slots by `UOP_BUFFER` identity, so a second copy of one input pushed the real inputs to higher slots and declared them with the wrong C type: every amax / amin gradient and the ATP listwise loss gradient read float bits as int (1.0 came back as 1065353216) on the C JIT, and the cat tests ran 3-5x slower (59 s for one test, 12 s after).  `test_uop_mov_cache_growth`: 3/5 before (11.5 s), 5/5 after (0.2 s); the 54 failures the full py suite showed after `test_cat_parity` are gone.
- A broadcast EXPAND over a view that realized to a BUFFERIZE reads that buffer at its own input ranges (0 on the broadcast axes), as a non-realized SHRINK or FLIP already did; it forwarded the bare buffer, which its consumer indexed over the expanded extent, past the end of the buffer.  One weight read by matmuls of different row counts (the ATP history table's levels through one `nn.Linear`, tools/atp_enigma/history_net.py) realizes the weight's RESHAPE and broadcast it this way, so every level after the first read garbage or NaN: `test_shared_weight_levels` 1/2 before, 2/2 after on the C JIT and the UOp walker, and py `test_cat_parity::test_levels_of_different_widths_share_one_linear` fails before and passes after.  The bug predates the G2 branches (it reproduces at 2185bba8); the lazy `Tensor.cat` exposed it.
- `docs/gather_scatter.md` states which tinygrad kernels the amax NaN probe ran: master gives nan among 8 ids and -inf among 40 ids with include_self and 2.0 without it for [nan, 1, 2] on one position; the sentence had attributed the -inf to 40 ids alone.
- `test_uop_scatter_max` checks the identity bytes of fp8e4m3 (0xFE / 0x7E, its +-448) and fp8e5m2 (0xFB / 0x7B: a kernel store saturates +-inf to +-57344, as tinygrad master's does) next to the other eight dtypes, both matching tinygrad master on the pod, and a computed base fused into a MAX / MIN scatter's stores, which the no-include_self init reads twice: 1327/1327 on both CPU routes.
- `UOP_SCATTER` with MAX or MIN lowers like SUM: the read-modify-write combines with tinygrad's CPU forms `(acc < x) ? x : acc` and `(x < acc) ? x : acc` (codegen/decomp/op.py:84, folded `acc = MAX(acc, x)` as codegen/__init__.py:203 does), the stores start from the dtype's exact minimum or maximum (`scatter_identity_bits`), include_self combines base last, and without it an untouched position holds `I (op) base`, so an untouched NaN base becomes I as in tinygrad. Ties keep the first value in index order, a NaN src never wins (tinygrad's unrolled one-hot reduce lets a NaN at the head of a chunk win; docs/gather_scatter.md), and, apart from a NaN base outside the index's extent (tinygrad keeps it for some shapes, thvm always gives I), every other value matches tinygrad master bit for bit (f32 ties, signed zeros and identity hits, int32 / uint32 / int8 / uint8). `test_uop_scatter_max` covers both CPU routes, eight dtypes' identity bytes, a computed src, a base view, BEAM=2, JIT replay and a GC of live graphs: 235/557 before (declined), 1115/1115 after. PROD is still declined.
- The arange / reduce-collapse rewrite visits each node of a kernel's store DAG once at any size: its memo doubles at half load where it stopped memoizing at 8192 entries, and a reduce whose body is not an IWHERE (rule (2)'s only form) declines before its body is walked. Past the old cap every shared sub-DAG was re-walked once per path, a cost that doubles per level of sharing, so the kernels of a table grown by 22 `table.cat` steps never finished lifting (`test_uop_reduce_collapse`: killed by its 60 s alarm before, 37/37 in under a second after); a 64-step table's gradient realizes in 11 s where the body walks alone took 34 s.
- A gather's or scatter's operand that views a node realized for another reason (a view several consumers read differently) reads that node's buffer, the storage its kernel binds and the arena keeps alive for the read. `ru_index_leaf` stopped only at a node realized for the indexed op, so it composed the address on down to the buffer below, whose bytes the arena could already have handed to a later kernel: the gradient of three gathers from one table, under a dim-1 cat over a dim-0 cat of the gathered pieces, read recycled bytes (`test_uop_scatter` 374/375 before, 375/375 after, on the C JIT and the UOp walker).
- A broadcast EXPAND shared by consumers that read it through different views of an axis it passes through gives that axis a fresh range, which each consumer rebinds to its own: the reads tinygrad's realize then `remove_bufferize` substitution give (schedule/rangeify.py:50-91). The share-as-view shortcut gave every consumer consumer 0's range, and a compound one (a PAD's valid, a SHRINK offset) cannot be rebound, so the other consumers read the source at consumer 0's index: two adds of one bias, concatenated along dim 1, read the bias at the wrong column (`test_expand_shared_view` 9/13 before, 13/13 after, on the C JIT and the UOp walker).
- The gather / scatter C tests (`test_uop_gather`, `test_uop_scatter`, `test_grad_gather_scatter`, `test_bypass_gate_view_offset`) name `THVM_CPU_JIT_WARMUP=1000000000` alone as their UOp-walker run: the precompile and both JIT caches honor the warmup gate, so the `THVM_CPU_JIT_PARALLEL=0` and opt-tag workaround they recommended is not needed.
- `test_bypass_gate_view_offset` and `test_autotune_iso_extent` (from the gather/scatter branch, whose fixes main already holds as 6b15789d, 73062fab and 9adca130) pin a gate-tripped kernel's composed-view marks and the BEAM isolated search's scratch: a row sum over `W[t]` (a SHRINK view) plus a broadcast scalar marks every offset slot `input_chain_composed` and walks exactly on the JIT and the UOp walker, every input slot's scratch holds the largest index its view chain reaches, and `BEAM=2` realizes rows at the end of a 200000-row table.
- `try_inline_bufferize_1axis_via_decomp` is `noinline`, like the other bufferize helpers of the walker rewrite: its decomposition stacks make a 4784-byte frame (gcc 11 -O2), which inlined into `unified_rewrite_rec_sub` would sit on every level of that recursion, the frame growth that overflowed the 8 MB Linux stack on a 2000-deep chain before 911589c0. gcc 11 and clang 14 keep it out of line today; the attribute holds that.
- A gather's index and a scatter's base that are views of storage (a
  view-alias TEN with an offset or a PERMUTE, a lazy SHRINK or FLIP) are
  read through their storage like the other indexed operands
  (`ru_index_leaf`, bound by `visit_indexed_leaf`).  The elementwise read
  they used before dropped an alias's offset and strides on both CPU
  backends, and on the UOp walker misread a lazy row or column SHRINK (out
  of bounds for a scatter base).  A computed index or base still fuses.
- `UOP_SCATTER` with SUM or REPLACE lowers to its own kernel: an AFTER chain
  of stores (init, a reset for include_self=0, a serial read-modify-write
  over the index space, and for SUM with include_self a final `+ base`, so
  the result is tinygrad's S + self, mixin/op.py:1127).  An invalid index
  writes the old value back; duplicates combine in ascending order along
  dim, so REPLACE is last-write-wins.  O(|base| + |idx|) work, CPU backend
  only, JIT replay with the index rewritten in place.  PROD / MAX / MIN
  are declined until they get a lowering.
- `UOP_GATHER` lowers to a guarded indexed load (the collapsed one-hot form
  of tinygrad's pm_reduce_load_collapse, codegen/simplify.py:143-145): one
  load per output element, no REDUCE, fused into its consumer.  The
  gathered operand is read through its views down to storage; a computed
  operand realizes first (`BUFFERIZE_REASON_INDEXED_SRC`).  Gather kernels
  run on the CPU backend only, including JIT capture and replay with the
  index rewritten in place; V=1e4, N=1024, D=64 realizes in ~1 ms (C JIT)
