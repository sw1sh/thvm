## Next moves

1. **Memory ceiling**: the VampirePortfolio @ 120s exits with 137/139 on `WolframAxioms/ImpliesHillmanAxioms`, `WolframAxioms/OrAssociativity`, `WolframAxioms/AndAssociativity`, `ShefferAxioms/Implies{Wolfram,WolframAlternate}Axioms`.  These are not "search-too-shallow" failures -- they OOM.  Either cap Vampire's `--memory_limit` lower, or shard the proof attempt with axiom-relevance pre-filtering.
2. **Sheffer-direction asymmetry**: every PROVED reaches *out of* Sheffer faster than into it (`ImpliesWolframCommutativeAxioms` 32.94s) while `ImpliesHillman`, `ImpliesMeredith`, `ImpliesWolfram*` all time out / crash.  Sheffer's single-axiom-set structure makes its forward direction expensive under standard term orderings.  Try **LPO with the Sheffer `nand` symbol set lowest** (inverse of the WM Sheffer preset) to encourage rewrites *into* the target system rather than away from it.
3. **`McCuneAxioms/EqualityOfInverses` + `RobbinsAxioms/DoubleNegation`** -- both classical "well-known hard" cases.  Worth a dedicated 600s+ Waldmeister run with the Hauptkomponenten-style (main-component) RHS-interreduce on, since the WM literature shows these in the 600-1000s range, not 60-120s.
4. **`WolframCommutativeAxioms/ImpliesHillmanAxioms`** -- now PROVED at 46s.  Record the winning sweep config in the TSV (extra column) so future regressions can reproduce the crack.
5. **Plot regeneration**: the three-prover bar charts now reflect the
   83-theorem intersection (was 72).  The 23-theorem gap "WL or Vamp but
   not thvm" identifies the concrete future-work backlog; 4 of those are
   "Vamp only" (neither thvm nor WL crack them) so they're a joint
   benchmark target, not a thvm-specific gap.

## Pass 3 — per-conjunct visibility (2026-06-02)

The residual 22 are reported as "Failed" / "TimedOut" / "CRASH" under
the in-process multi-conjunct dispatcher (`atpProveFromTheory` in
ATP.wl), which collapses any List of proofs to `$Failed` if ANY
conjunct fails.  Twelve of the 22 residuals are multi-conjunct
(2 or 3 equations); the all-or-nothing collapse was hiding genuine
partial progress.

New per-conjunct bench harness (`tools/baselines/run_thvm_per_conjunct.sh`
+ `list_conjuncts.wls` + `run_thvm_one_conjunct.wls`) drives each
conjunct in its OWN fresh wolframscript subprocess so a per-conjunct
SIGSEGV cannot lose the prior conjuncts' results.  Output:
`tools/baselines/thvm_per_conjunct.tsv` + rolled-up summary
`tools/baselines/thvm_per_conjunct_summary.tsv`.

### Engine bug: multi-conjunct SIGSEGV

WolframAxioms/ImpliesMeredithAxioms reproducibly SIGSEGVs the kernel
on conjunct 2 (the easy `(x*y)*(x*z) == x` form).  The in-process
dispatcher's Table iteration triggers it; standalone per-conjunct
calls also crash with the same target.  Survives the broader
g_atp_dt_*/ri_*/cp_q* pointer-cache NULL'ing in commit 0c7d100a, so
the corruption is in a different code path (likely the
proof-reconstruction trace[] or the Automatic-portfolio inner slot
swap).  Filed for the engine arc; the per-conjunct harness's
process-isolation means this doesn't poison the other rows.
