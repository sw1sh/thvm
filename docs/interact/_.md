# Interactions

Each rule lives in its own file under [src/interact/](../../src/interact/).
The rules listed under "Documented" have matching pages here; the C file's
leading comment mirrors the sequent rule from the page, and if they disagree
the page wins. The rules under "Documented in source only" carry their
sequent rule in the C file's leading comment and have no page yet.

## Documented in source only

ICC bridging (`θ`-binder) rules:

- **ANN-BRI** (`ann_bri.c`): when the type is itself a Bridge, the annotation flushes; the bridge's bound `x` is substituted by `val` and the body is returned as-is.
- **ANN-LAM** (`ann_lam.c`): mirror of APP-BRI; introduce a fresh `$k` bound by an inner Bridge, substitute the LAM's binder so occurrences of `x` in the body are now `θ`-wrapped, and wrap the result in a new outer LAM.
- **APP-BRI** (`app_bri.c`): ICC type-backward-flow; rewrites `(APP (θx. body) arg)` into `θx. (APP body[x ← λ$k. x] (ANN $k arg))`, sharing `$k` between the inner LAM binder and the annotated value.
- **DUP-BRI** (`dup_bri.c`): mirror of DUP-LAM for Bridges; commutes a duplicator past `θx. body` into two fresh Bridges with bodies projected through a sub-DUP and `x` bound to a SUP of the new binders.

Primitive and superposition specials:

- **APP-PRI** (`app_pri.c`): accumulates `arg` into the PRI's argument buffer, and once the buffer matches arity calls `PRIM_TABLE[id].fn` with the args; otherwise returns a new PRI pointing at the larger buffer.
- **APP-SUP** (`app_sup.c`): distributes an application across the two children of a SUP via a shared DUP on `arg`, producing `&L{ APP(f, x0), APP(g, x1) }`.

Dynamic-label superposition and duplication (the label is itself a term,
reduced first):

- **DSU-NUM** / **DSU-ERA** / **DSU-SUP** (`dsu_num.c`, `dsu_era.c`, `dsu_sup.c`): `&(#n){a, b}` becomes the SUP with label n; an erased label erases; a superposed label commutes the dynamic SUP into both branches.
- **DDU-NUM** / **DDU-ERA** / **DDU-SUP** (`ddu_num.c`, `ddu_era.c`, `ddu_sup.c`): the same three cases for a dynamic-label DUP `! X &(lab) = v; b`.

Structural duplicators and SUP distribution:

- **DUP-CTR** (`dup_ctr.c`): duplicates a constructor field by field, `#K{a, b, ...}` into `#K{A0, B0, ...}` and `#K{A1, B1, ...}`.
- **DUP-NOD** (`dup_nod.c`): the generic form for any n-ary node `T{a0, ..., a_{n-1}}`.
- **APP-MAT-SUP** (`app_mat_sup.c`): a MAT applied to a SUP distributes over both branches, sharing its handlers through DUPs.
- **OP2-SUP** (`op2_sup.c`) / **OP2-NUM-SUP** (`op2_num_sup.c`): an OP2 whose left (or, with a NUM left, right) operand is a SUP distributes over both branches.

Atomic-payload duplicator annihilations:

- **DUP-ANY** (`dup_any.c`): ANY is atomic with no payload, so each projection is a fresh ANY term.
- **DUP-NUM** (`dup_num.c`): NUM is atomic; projections simply copy the Term value into both sides.
- **DUP-TEN** (`dup_ten.c`): TAG_TEN is an atomic tid handle; both projections reference the same tensor by id with no heap copy.

UOp interactions:

- **DUP-UOP** (`dup_uop.c`): commutes a duplicator past a compute UOP by replicating the UOP at each projection side and pushing fresh DUPs into its compute-input slots; "active" UOPs (KERNEL/GRAD/FWD/ASSIGN) are intentionally left stuck.
- **UOP-ASSIGN** (`uop_assign.c`): in-place buffer write fired once both children resolve to TAG_TEN; copies `src.buf` bytes into `dst.buf` while preserving dst's tid/buf_id/view, so optimizer loops can mutate weights tid-stably.
- **UOP-GRAD** (`uop_grad.c`): dup-like, gy-threaded chain rule for the BWD projection (TAG_DP1 + DUP_GRAD_FLAG) of a grad cell; each fire walks one structural step on `y`'s outermost UOp and emits a SUP at TEN leaves so the outer DUP at the WL surface picks the matching leaf's cotangent.
- **UOP-KERNEL** (`uop_kernel.c`): fires a UOP_KERNEL once all inputs are TAG_TEN, recursively firing upstream producer kernels first so every input buffer is populated, then dispatches through `Backend->dispatch_kernel` and returns the output TAG_TEN.

## Counting interactions

Each rule increments the global `ITRS` counter exactly once when it
fires. C tests assert the delta:

```c
u64 before = ITRS;
Term out = wnf(some_term);
CHECK_EQ(ITRS - before, expected_count);
```

WL tests do the same via `TItrs[]`.
